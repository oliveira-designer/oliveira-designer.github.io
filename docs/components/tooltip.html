Tooltip

Short text hint on a dark bubble with an arrow, in four placements: Top, Bottom, Left and Right. It opens 300 ms after mouse hover or keyboard focus on its trigger, closes at once when hover and focus leave, can be reached by the pointer, and is dismissed with Escape. It never appears on touch. No Toggletip.

When to use

  • A short label that explains an icon-only control, such as an Icon Button.
  • A hint that repeats something the page already says: the tooltip is never the only place for essential information.

Behavior

  • Show: 300 ms after mouse or pen hover on the trigger, or after keyboard focus (:focus-visible) on it. The two delays are product decisions of the Hope DS, not values from a standard (gap tooltip-delay-values).
  • Hide: at once when neither the trigger nor the tooltip has hover or focus. The close waits only one task (setTimeout of 0 ms), so the pointer can go from the trigger to the bubble. There is no timeout while hover or focus stays.
  • Hoverable (WCAG 1.4.13): the pointer can cross the 8px between the trigger and the bubble because an invisible pseudo-element of the tooltip covers that gap. The close stays immediate.
  • Dismissible (WCAG 1.4.13): Escape hides it without moving the focus. The key is consumed, so a Modal or a Bottom Sheet that contains the trigger stays open: the first Escape closes only the tooltip and the second closes the dialog. After Escape the tooltip stays hidden until hover and focus have both left the trigger.
  • Touch: a tap shows nothing. Pointer events count only for mouse and pen, and the focus a tap gives a button is ignored because it does not match :focus-visible. Nothing essential may depend on a tooltip, because it never appears on touch.
  • Hidden state: the hidden attribute (display none), so the tooltip is out of the page flow and the accessibility tree while hidden. The trigger keeps aria-describedby. Whether a screen reader reads a hidden description once and not twice was not tested (gap tooltip-screen-reader).
  • No animation is added, so prefers-reduced-motion has nothing to change.
  • Inside a Modal or a Bottom Sheet the tooltip flips and shifts to stay inside the dialog (the nearest container that clips it), so it is not cut and stays attached to its trigger. It can cover part of the dialog, for example the footer when it is placed below a trigger at the bottom of a scrolling body.

Positioning

  • Four placements, the names of the Figma set: data-placement="top|bottom|left|right". Default Top, centered on the trigger (data-align="center"), 8px away (--space-2).
  • Flip: if the preferred side does not fit in the viewport and the opposite side does, the tooltip goes to the opposite side and the class tooltip--top|bottom|left|right follows. If neither fits, it stays on the side with more room.
  • Edges: if it still passes the screen edge, the bubble is shifted to stay 16px (--space-4) inside.
  • Clipping container: the flip and the shift measure against the viewport intersected with the nearest ancestor that clips the tooltip (computed overflow, overflow-x or overflow-y other than visible), with the same 16px margin (--space-4), so the bubble stays inside that container and attached to its trigger. The ancestors that count are the ones in the containing block chain of the tooltip. Menu, Popover and the Breadcrumb panel do not do this: they measure against the viewport only (and are not supported inside a Modal or a Bottom Sheet). If no side fits, the side with more room is kept.
  • Arrow: when the bubble is shifted, the arrow keeps pointing at the center of the trigger, in all four placements. js/position.js sets the custom property --tooltip-arrow-offset (from the center of the bubble) and the CSS translates the arrow by it. The offset is clamped so the arrow stays clear of the rounded corners: half the bubble minus the bubble radius minus half the arrow. When the center of the trigger is out of that range, the arrow stops at the limit (data-arrow-clamped="true").

The four placements as the specimen of the component, always visible and placed against a trigger by js/position.js (data-anchor). They show the shape; the live example above shows the behavior.

Accessibility

The trigger points to the tooltip with aria-describedby and the tooltip has role="tooltip". The text is a hint, not the only name of the control: an icon-only control keeps its own accessible name (aria-label). A tooltip does not appear on touch, so it never holds the only way to reach essential information.
