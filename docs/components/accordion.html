Accordion

A stack of items whose header opens and closes a panel of content. Each item has a title, a chevron and a bottom border; an open item shows its content.

When to use

  • Content in short sections that the person opens only when needed, such as answers to common questions.
  • The list is composed of stacked items (the Figma text).
  • Items open independently.

When not to use

  • Content that has to be read in full: show it on the page.
  • Switching between views of the same object: use Tabs.
  • A list of actions: use a Menu.

Anatomy

  • Item: padding 16, gap 8, only a bottom border of 1px. The last item keeps its border.
  • Header: a button with the title (Body/SemiBold/body-sm semibold) and a CaretDown of 20px at the right, 12 apart.
  • Panel: the content (Body/Regular/body-sm, Text/Default/Secondary), hidden when closed.

States

Accordion states, what changes in each and the tokens involved
State What changes Tokens
Closed The panel has the hidden attribute, aria-expanded="false", the chevron points down. --icon-color-secondary
Open The panel shows, aria-expanded="true", the chevron is rotated 180 degrees. --color-text-2
Hover The whole item takes Background/Default/Secondary, open or closed. --color-bg-alt
Focus A ring around the WHOLE item (4px outside each side), square, though the focus is on the header button. --focus-ring-width --focus-ring-gap --color-border-focus-ring
Disabled (closed only) Title and chevron in the Disabled tokens, no opacity. Uses the disabled attribute. --color-text-disabled-default --icon-color-disabled

Keyboard and ARIA

Accordion keyboard interaction
Key Action
Enter and Space On the header: open or close the panel.
Tab and Shift+Tab Move between the headers (and into the content of an open item).
  • The header is a <button> with aria-expanded and aria-controls pointing at the panel. It sits inside a heading; the level is the author's.
  • The panel has role="region" and aria-labelledby (the header) only when the list has 6 items or fewer; with more, both are omitted so the landmark list is not flooded. js/accordion.js applies the rule.
  • A closed panel uses the hidden attribute, so it is out of the accessibility tree.
  • Disabled uses the disabled attribute.

Classes and tokens

Accordion classes, what each is for and the tokens its rule uses
Class Used for Tokens
.accordion__item One item: padding 16, bottom border 1px, hover fill, focus ring on the whole item. --space-2 --space-4 --font-body --border-width-normal --color-border

Code notes

Accordion code notes, the status of each and the detail
Note Status Detail
accordion-disabled-open documented Figma draws Disabled only for the closed item (7 variants). An open and disabled item is not designed; in code a disabled item should be closed.
accordion-no-motion documented Figma defines no height animation, so the panel appears and disappears at once and the chevron turns without a transition. There is nothing to remove under prefers-reduced-motion.
accordion-border-contrast measured The bottom border (Border/Default/Default) is 1.29:1 against the page in Light and 1.28:1 in Dark, and 1.21:1 and 1.14:1 against the hover fill, under the 3:1 of WCAG 1.4.11. It separates items and the title carries the information. Implemented as in Figma, no color changed. Accepted by Renan, 2026-11-24. Reevaluate: when dark mode lands, or with real use.
accordion-focus-has documented The ring on the whole item uses :has(.accordion__trigger:focus-visible). Where :has() is not supported, a plain ring on the header button is used instead. The focused item is raised one layer (--z-raised) so the ring is not painted under the next item.
accordion-no-js documented Without JavaScript the items stay closed (the panels have the hidden attribute) and their content is not readable. Accepted: showing the content by default was considered and rejected, because an open Accordion on first load can push other elements out of view and looks wrong. The role="region" rule by item count is applied by the script. Accepted by Renan, 2026-11-24. Reevaluate: with real use.
accordion-site documented The site has no accordion or FAQ pattern, so no page was aligned. design-system.html uses <details> for code blocks, which is a different pattern and was not changed.
